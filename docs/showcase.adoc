[#intro]
== Document header and metadata

The header above carries a title, two authors with email addresses, a revision
line (`v1.0.0, 2026-04-25: First public showcase`), and a block of attribute
entries.
Attributes are referenced inline with curly braces — for example, you are
reading version {product-version} of {product}, and the homepage is
{homepage}.

A `:toc:` attribute placed in the header pulls a Table of Contents above this
introduction; `:sectnums:` numbers every heading; `:sectanchors:` adds a small
hover anchor next to each heading so headings can be linked directly.

== Paragraphs, line breaks, and inline quoting

Paragraphs are separated by blank lines.
A trailing space-plus (` +`) at the end of a line forces a hard +
break, so the second half of this sentence starts on its own line.

Inline quoting uses constrained pairs around a word — *strong*, _emphasis_,
and `monospace` — or unconstrained pairs that work mid-word: **bo**ld,
__it__alic, ``mo``no.
Combinations nest naturally: *_strong emphasis_*, *`bold mono`*.
Specialchars are escaped automatically, so `1 < 2 && 3 > 2` survives as
literal text without breaking the HTML.

Character replacements turn (C), (R), (TM), ..., -- and -> into typographic
forms; arrows fire in both directions (<-, <=, =>).

[#inline-extras]
== Inline extras: subscript, superscript, highlight, passthroughs, footnotes

Water is H~2~O, Einstein had E=mc^2^, and you can #highlight a phrase# inline
with hashes (or with ##unconstrained## pairs mid-word).

A constrained passthrough +keeps *stars* and {attrs} literal+, while the
unconstrained ++**double stars** also survive++ verbatim.
The `pass:[...]` macro emits raw HTML — pass:[<kbd>Ctrl</kbd>+<kbd>C</kbd>]
renders as keyboard keys.

Footnotes attach inline.footnote:[Here is an anonymous footnote with
_emphasis_ inside it.]
You can also id a footnote so it can be referenced later:
footnote:fn-spec[The AsciiDoc Language specification at https://docs.asciidoctor.org/asciidoc/latest/].

[#admonitions]
== Admonitions

NOTE: A short note rendered as a paragraph admonition.

TIP: A tip — paragraph form, default label.

IMPORTANT: An important call-out you really shouldn't skim past.

WARNING: A warning, often used for irreversible operations.

CAUTION: A caution — slightly softer than a warning.

.A titled admonition
[NOTE]
====
Block-form admonitions can hold multiple paragraphs and other content.

The leading `.A titled admonition` line replaces the default _Note_
label with a custom title.
====

[#source]
== Source blocks with language

A `[source,LANG]` attribute on a listing emits a `language-LANG` class on
the inner `<code>` element so downstream highlighters (Prism, Highlight.js,
Rouge) can take over without conflict.

.A Rust function with a language hint
[source,rust]
----
fn main() {
    let greeting = "Hello, AsciiDoc!";
    println!("{}", greeting);
}
----

.A Python snippet
[source,python]
----
def fizzbuzz(n: int) -> str:
    if n % 15 == 0:
        return "FizzBuzz"
    if n % 3 == 0:
        return "Fizz"
    if n % 5 == 0:
        return "Buzz"
    return str(n)
----

.A Bash one-liner
[source,bash]
----
adoc --emit-ast doc.adoc | jq '.blocks[0]' | adoc --from-ast -o filtered.html
----

[#preprocessor]
== Preprocessor: includes, conditionals

The `include::` directive pulls another file into this document at parse time.
Two regions of `docs/showcase-snippet.adoc` are selected by tag below.

.From `docs/showcase-snippet.adoc`, `tags=intro`
include::showcase-snippet.adoc[tags=intro]

.From the same file, `tags=trailing`
include::showcase-snippet.adoc[tags=trailing]

The `ifdef::` / `ifndef::` / `ifeval::` directives gate content on whether
attributes are set or on simple expressions.

ifdef::edition[We are publishing edition {edition} of this showcase.]

ifndef::draft[This paragraph is shown because `draft` is **not** defined.]

ifeval::[{edition} >= 2]
And `ifeval::[{edition} >= 2]` is true here, so this conditional block renders.
endif::[]

[#cli]
== Stdio extension model

The AST round-trips through `serde_json`, so external tools can post-process
documents as a Unix-style pipeline:

[source,bash]
----
# Render directly
adoc docs/showcase.adoc -o docs/showcase.html

# Or pipe through a custom filter
adoc --emit-ast docs/showcase.adoc \
    | jq '.blocks |= map(select(.kind != "comment"))' \
    | adoc --from-ast -o docs/showcase.html
----
